# Static publisher

The site is plain HTML generated by this folder. There is no Hugo or Jekyll build to run. Every post is stored as a JSON record in `_publisher/posts/<slug>.json`, and each publish rebuilds every generated page from all records with `sitegen.py`. The same records always give the same files, so a publish that changes nothing reports `no file changes`.

The publisher lives in `_publisher/` because GitHub Pages runs Jekyll on this repository, and Jekyll does not publish directories whose names start with `_`. Nothing here is linked from the site. If a `.nojekyll` file is added later, this folder would be copied to the site as ordinary files; it would still not be linked.

Requires Python 3.9 or newer. The standard library is enough (`zoneinfo` dates). No packages to install. On Windows, set `PYTHONUTF8=1`.

## Publish a post

From the repository root:

```bash
python3 _publisher/publish.py \
  --title "Luna 全双工语音日报（2026-11-20）" \
  --date 2026-11-20 \
  --slug lumi-2026-11-20 \
  --category 日报 \
  --tag lumi \
  --headline "一句话说清当天最重要的消息" \
  --body-file ./digest.md
```

Suggested URLs:

- `/post/lumi-YYYY-MM-DD/` with category `日报` and tag `lumi`
- `/post/agent-app-YYYY-MM-DD/` with category `日报` and tag `agent-app`
- `/post/trading-YYYY-MM-DD/` with category `每日交易资讯` and tag `每日交易资讯`
- `/post/learn-agent-YYYY-MM-DD/` with category `Agent 学习笔记` and tags for the project or topic (`TradingAgents`, `LangGraph`)

`--category` and `--tag` can be repeated. A category is required; the first one is the post's column. Tags are optional. The visible name is kept (`Agent App` stays `Agent App`) and the directory is a lowercase slug (`agent-app`, `日报`).

`--date` is interpreted in Asia/Shanghai. A date with no clock time uses 08:00:00. A value that already has a zone (`2026-11-17T00:30:00Z`) is converted to Shanghai time.

The body is Markdown unless you pass `--format html` or set `"format": "html"` in JSON. The post page prints the title, so the body should start with the text rather than a heading that repeats the title. Put `<!--more-->` on its own line to choose the listing summary (every paragraph before that line); otherwise the summary is the first paragraph. `--summary` and `--description` override those.

`--headline` is optional. It is the one-line heading of the post's homepage card, such as `Reson8 开源 0.5B 手机级 ASR`. Without it the card shows the title without its date (`Luna 全双工语音日报`). The headline is not shown on the post page.

JSON input (flags override the same fields when you pass them):

```bash
python3 _publisher/publish.py --input post.json
```

```json
{
  "title": "Luna 全双工语音日报（2026-11-20）",
  "date": "2026-11-20",
  "slug": "lumi-2026-11-20",
  "categories": ["日报"],
  "tags": ["lumi"],
  "headline": "一句话说清当天最重要的消息",
  "body_file": "digest.md",
  "format": "markdown"
}
```

`--body-file -` reads the body from stdin. `--dry-run` prints the files it would write and writes nothing. Publishing the same slug again replaces that post instead of adding a second copy. `--root` defaults to the repository root.

Other commands:

```bash
python3 _publisher/publish.py --remove lumi-2026-11-20   # delete a post and rebuild
python3 _publisher/publish.py --rebuild                  # regenerate every page from the records
```

Run `--rebuild` after changing `sitegen.py`, the column list, or the bio, then commit the pages it writes.

## Columns and the homepage

The columns are listed in `COLUMNS` in `sitegen.py`, in nav order:

| Category | Nav | Homepage section |
| --- | --- | --- |
| `日报` | 日报 → `/daily/` | The newest day's posts as cards, then the 3 posts before them as a list. |
| `每日交易资讯` | 交易资讯 → `/categories/每日交易资讯/` | The 2 newest posts. |
| `Agent 学习笔记` | 学习笔记 → `/categories/agent-学习笔记/` | The 3 newest posts. |

A post whose category is not a column still gets its own category page, and the homepage shows it in a section named after that category below the columns. Every category and tag has a page and an RSS feed.

Listing summaries leave out opening lines that start with `时间窗口`, `覆盖范围`, or a date such as `2026年`; those lines show on the post page. A `日报` card adds `· N 条` when the summary says `本期 N 条`.

A title of the form `Agent 学习笔记（2026-11-19）：什么才算 agent` shows as `什么才算 agent` on the post page and in listings, because the column and date are already shown beside it. Other titles show as written.

## Post pages

Opening paragraphs that start with `时间窗口`, `覆盖范围`, or a date such as `2026年` are marked `class="digest-meta"` and shown as a boxed lead. A blockquote that opens with one of these bold labels becomes a colored callout on any post:

```markdown
> **原则：** 需要判断力的决策交给模型。   (green; also 要点, 我的理解)
> **思考题：** 为什么这样设计？           (amber)
> **修正：** 不是反思。                   (red)
> **举一反三：** 换个系统也成立。         (indigo)
```

Other blockquotes stay plain. Each post page links the previous and next post in the same column and loads utterances comments (GitHub issues on this repository, matched by path).

Styles are in `css/site.css` and the theme switch and comments loader in `js/site.js`. Both are hand-written; the publisher never rewrites them, and page links carry a `?v=` hash of the two files so browsers pick up changes. The theme follows the system setting until the reader picks one with the switch, which is then remembered in that browser.

## Daily feed

`/daily/` is the filterable feed for these briefs. Long posts such as `/post/lumi-2026-11-17/` stay as archives. The page is static HTML, CSS, and JS in `daily/` (Jekyll publishes that directory). `daily/index.html` is copied from `_publisher/templates/daily.html` on every publish, so edit the template, not the page.

Items live in `daily/items.json`. The feed shows a 领域 or 类型 only when at least one item uses it. Counts beside those names follow the current search, relevance, and date, and ignore the domain, type, and tag checkboxes. 相关度 is a 1–5 score against Yonas's interests: agents (architecture, harness, memory, planning, tool use and MCP, multi-agent, computer use, coding agents, long-horizon reliability), LLMs, physical AI / embodied intelligence, and on-device iOS voice agents (Luna). Do not mark every item as 5.

`date` is the Asia/Shanghai calendar day of the digest (`YYYY-MM-DD`, no clock time).

### Item JSON

`daily/items.json` is a list. The publisher upserts by `id` and rewrites that file plus `daily/index.html`. Pass a list, or an object with an `items` array. Unknown fields are rejected.

```json
{
  "id": "lumi-2026-11-17-voice-reader",
  "date": "2026-11-17",
  "seq": 1,
  "source_brief": "lumi",
  "title": "一句话摘要。",
  "summary": "讲解。",
  "insight": {"heading": "对 Luna 的启发", "body": "只在来源里已有这段时填写。"},
  "relevance": 4,
  "domains": ["语音 Agent", "端侧"],
  "types": ["模型发布"],
  "tags": ["Pipecat"],
  "source": {"name": "", "handle": "@JonPTaylor", "identity": ""},
  "links": [{"label": "原帖", "url": "https://example.com/post"}],
  "archive_url": "/post/lumi-2026-11-17/",
  "posted_at": "11-16 20:05"
}
```

`insight` may be omitted or `null`. `posted_at` is optional and is the source's own time string; leave it out when the digest date already says it. `seq` orders items inside the same day (当天日报第 N 条). If you omit `seq` on a new id, the publisher appends one. `source` needs a `name` or a `handle`. Link URLs are `http(s)` or a site path.

Publish items alone:

```bash
python3 _publisher/publish.py --items _publisher/drafts/items-2026-11-17.json
```

An `--input` object may include both post fields and `items`. The post is written only when a markdown or HTML body is present. Item ids already in `daily/items.json` are replaced; other items stay. `daily/feed.css` and `daily/feed.js` must already be in the site; the publisher does not regenerate them.

## Learning calendar

`/learn/` is the calendar for the agent study plan. Weeks can be appended to `plan.json` to extend it. Like `/daily/`, it is static HTML, CSS, and JS: `learn/index.html` is copied from `_publisher/templates/learn.html` on every publish (edit the template, not the page), and `learn/learn.css` and `learn/learn.js` are hand-written. The nav link 学习进度 points to it.

The page reads two data files in the browser, so updating progress needs no rebuild:

- `learn/plan.json`: the fixed day-by-day plan. Weeks hold days; each day has `date`, `label` (shown in the calendar cell), `goal`, and `tasks` (`id`, `text`, `min`). Task ids are `YYYYMMDD-N`.
- `learn/log.json`: what was actually learned, keyed by date: `done` (task ids from `plan.json`), `summary` (one line, shown in the cell), `points` (2–4 bullets in the day view), and `note` (the site path of that day's 学习笔记 post, or empty).

Ticks made on the page stay in that browser (localStorage) and are labelled 本机 until `log.json` lists them.


```bash
python3 _publisher/test_publish.py
```

The tests build throwaway copies of the site and do not touch this checkout. One of them fails when the committed pages differ from a fresh build of the records; run `--rebuild` and commit to fix it.

## Files that change

A publish writes only files whose text changed:

| Path | What it is |
| --- | --- |
| `_publisher/posts/<slug>.json` | The post record: title, headline, date, categories, tags, description, summary HTML, body HTML. |
| `index.html` | Homepage: intro and one section per column. |
| `post/<slug>/index.html` | Each post page. |
| `post/index.html` | 归档: every post by year. |
| `categories/<slug>/`, `tags/<slug>/` | A page and an RSS feed for each category and tag. |
| `categories/index.html`, `tags/index.html` and their `index.xml` | All categories and tags. |
| `index.xml`, `post/index.xml` | Site RSS: every post, newest first. |
| `sitemap.xml` | Every page above, plus `/daily/`, with `lastmod` from the newest post (or digest item for `/daily/`). |
| `404.html` | Not-found page. |
| `daily/index.html`, `daily/items.json` | The feed page (from the template) and its items. |

A directory under `post/`, `categories/`, or `tags/` that no longer matches a post or term is removed when it holds only `index.html` / `index.xml`. If it holds anything else, it is left in place with a warning.

Hand-written files the publisher reads but never writes: `css/site.css`, `js/site.js`, `daily/feed.css`, `daily/feed.js`, `images/profile.jpg`, `favicons/favicon.ico`, `robots.txt`.

## Limits

- Posts from before 2026 were removed in the November 2026 redesign; old URLs get `404.html`.
- The bio, links, column list and footer are constants at the top of `sitegen.py`. Change them there and run `--rebuild`.
- Fenced code is not syntax-colored. Markdown covers headings, paragraphs, lists, links, images, emphasis, fenced code, tables, and blockquotes. Pass `--format html` when you already have HTML.
- Reading time counts about 400 Chinese characters or 200 English words per minute.
- GitHub Pages publishes the `master` branch. Commit the files a publish writes and push to `master`.
