覆盖范围：复习（回忆 8 题对 6 题）+ learn-claude-code s04 Hooks。今天聊了三件事：hook 是怎么把扩展挂到循环上的、为什么被拒绝的调用会从日志里消失、Stop hook 能让 harness 亲自检查"任务真的做完了吗"。

今天最大的收获是：**hook 链遇到第一个返回值就停，所以"把关"的 hook 会挡住排在后面的"旁观"的 hook**。课程里权限检查排在日志前面，被拒绝的调用一条日志都没有，而那恰恰是最该留记录的。计时 hook 是我自己设计的，三处位置都放对了；Stop hook 的风险，我漏掉了最隐蔽的一条：模型会去钻检查的空子。复习里，"收尾靠结构、不靠提示词"这一点我又错了一次。

## 今天学了什么

**1. s04 加了什么。**以前每加一个功能（记日志、权限检查、自动提交），都要改 agent 的主循环。s04 在循环的四个时刻留出挂钩，新功能挂上去，循环本身不用改：

| 事件 | 什么时候触发 | 返回了东西会怎样 |
| --- | --- | --- |
| UserPromptSubmit | 用户输入后、进模型前 | 不影响流程 |
| PreToolUse | 工具执行前 | 这次调用被拦下，返回的那段话成为工具结果 |
| PostToolUse | 工具执行后 | 不影响流程 |
| Stop | 模型不再调工具、循环准备结束时 | 循环不结束，那段话塞回给模型，让它接着干 |

**2. 把关的 hook 会挡住旁观的 hook。**触发 hook 的函数是这样写的：

```python
def trigger_hooks(event, *args):
    for callback in HOOKS[event]:
        result = callback(*args)
        if result is not None:   # 某个 hook 返回了东西 → 立刻停下
            return result
    return None
```

课程里先注册 `permission_hook`，再注册 `log_hook`。权限检查一旦拒绝，就返回了拒绝的理由，排在后面的日志 hook 根本跑不到。

> **原则：** 一票否决的"把关"，和每次都必须执行的"旁观"（记日志、计时、统计），不要放在同一条会中途停下的链上。实在要放，记录尝试的 hook 必须排在最前面。

**3. 我设计的计时 hook，和改前改后的对照。**要记下每次工具调用的耗时和返回长度，我的设计是：

- 开始计时挂在 `permission_hook` 之后：只量纯执行时间，被拒的调用走不到这里；
- 结束计时排在 `PostToolUse` 最前面：后面那些 hook 花的时间不算进来；
- 被拒的调用：在权限 hook 前后各挂一个 hook，"前面有记录、后面没有"就说明被拒了；
- 循环结束时，由 harness 打印一份清单。

整个过程一行都没改课程的循环，只往 hook 链上插东西。跑的任务是"写 count.py 统计 places.csv，运行它，然后删掉 count.py"，删除那一步被权限检查拒了。同一次运行里，课程原来的日志只有 9 行，被拒的那条 `del count.py & dir` 不在里面，收尾的统计也只说"用了 10 次工具调用"。我们的清单把 10 次全列了出来：

| # | 调用 | 结果 | 耗时 |
| --- | --- | --- | --- |
| 6 | `python count.py` | 执行了，返回 `(no output)` | 146.7 ms |
| 7 | `python --version & ... where python` | 执行了 | 280.3 ms |
| 8 | 用 anaconda 里的 python 运行 count.py | 执行了 | 86.2 ms |
| 9 | `del count.py & dir` | **被拒绝** | 没有执行 |

第 6、7 行都花在找 python 上：PATH 上的 `python` 是应用商店的占位程序，什么都不输出，退出码还是 0，是一次静默失败。真正执行只要 86 毫秒。

> **要点：** 这份清单是 harness 根据实际发生的调用生成的，不经过模型的嘴。模型的汇报漏掉了什么，看清单就能发现。

**4. hook 只能看到循环留了口的地方。**清单只量了工具执行的毫秒数，可真正贵的是多出来的模型调用：每一圈要等几秒，还要把整个历史重新发一遍。s04 在模型调用前后没有留挂钩，这部分量不到。线上真正有用的，是把很多次运行汇总起来看：多少任务在环境问题上浪费了圈数，返回 `(no output)` 的命令有多少，平均每个任务要跑几圈。

**5. Stop hook：模型说做完了，不算数。**

```python
if not tool_calls:
    force = trigger_hooks("Stop", messages)
    if force:                                   # Stop hook 返回的那段话
        messages.append({"role": "user", "content": force})
        continue                                # 塞回给模型，循环接着跑
    return
```

可以用它让 harness 亲自去检查：比如真的运行一遍 count.py，比对结果，没过就把原因塞回去，让模型接着改。这就是"评估者分离"：完成没完成，不由执行者自己说了算。

> **原则：** 用 Stop hook 时要守住三条：设上限，到了上限要交接；检查本身要对；检查要防模型钻空子。

## 我理解对的

- **被拒绝的调用，日志 hook 跑不到。**权限 hook 返回了拒绝理由，链就停了。
- **要让用户知道 agent 试过什么，就用 hook 在执行前记下来。**方向对，只是当时还不知道该挂在哪儿。
- **计时 hook 的三处设计都对。**"在权限 hook 前后各挂一个，前面有、后面没有就是被拒了"，不用改循环就能识别出被拒的调用。
- **找 python 的事应该交给 harness**，在代码里提前找好路径，不要让模型靠试错去摸。
- **Stop hook 可以让独立的检查来确认任务真的完成了。**风险也想到了两条：一直过不了检查会停不下来，要设上限；检查本身写错了，会给模型错误的指引。
- **复习里答对的 6 道**：LangGraph 是 agent 还是 workflow，看下一步由模型驱动还是代码驱动；多个分析师只交报告的好处和代价；专用工具改善的是接口；prompt、context、harness 三层的包含关系（第三次终于答对）；工具只交 stdout 时模型会怎样（也是第三次答对）；harness 的五个部分。

## 我理解错的、不够准的

> **修正：** 复习时我第二次以为，TradingAgents 到上限收尾时是"在提示词里禁止调工具"。其实它调用的是根本没挂工具的 `llm`，平时用的才是 `llm.bind_tools(tools)`；再加上收尾之后无论如何都结束的那条边，是双保险。

同一个点错两次，说明我读代码时还是习惯先看提示词写了什么，而不是先看请求里到底带了什么。

> **修正：** 我把收尾时"问用户要不要继续"理解成了权限问题。其实它问的是"要不要再给几圈去补数据"。TradingAgents 不问，是因为它无人值守、没人可问，默认的做法是带着缺口写完报告，流程继续。

> **修正：** 我说第 6 行"返回了错误"。其实它只返回了 `(no output)`，是静默失败，所以模型才要再花一圈去查。

> **修正：** 我只盯着工具执行的那几百毫秒。真正贵的是多出来的模型调用，而 s04 在模型调用前后根本没有挂钩，量不到。

> **修正：** Stop hook 的风险，我漏掉了最隐蔽的一条：模型会去满足检查，而不是完成任务。如果检查只看输出里有没有 `parking`，模型把 count.py 改成直接 `print("parking 1")` 就能过。

这在业界叫 reward hacking。防法是：检查要看真实的结果；检查依赖的测试和数据，要放在模型改不到的地方。

> **修正：** 我以为在 harness 的五个部分里，自己还没碰过 knowledge 和 action interface。其实 `run_bash` 和 `TOOL_HANDLERS` 就是 action interface，也就是真正去执行动作的"后厨"；system 里那句"bash 走 cmd.exe"就是 knowledge。

## 举一反三

**1. Claude Code 自己也有 hooks**，事件名几乎一样：PreToolUse、PostToolUse、Stop、UserPromptSubmit，可以在 settings.json 里挂命令。Stop hook 同样能拦下结束，把原因告诉模型。

**2. "把关"和"旁观"挤在同一条链上，是所有插件链、中间件的通病。**

| 场景 | 会中途停下的环节 | 被挡住的环节 |
| --- | --- | --- |
| s04 hook 链 | 权限检查拒绝 | 日志 |
| Web 中间件 | 鉴权失败直接返回 | 访问日志、耗时统计 |
| 审批流程 | 第一个审批人驳回 | 后面的抄送、归档 |

**3. 自我汇报靠不住时，让 harness 自己记账。**上一课模型的汇报漏掉了它夹带 Python 再试的那次；这一课的清单不经过模型，被拒的调用一目了然。

> **举一反三：** 评审一个 agent 的扩展机制时，先问两个问题：有哪些环节会中途停下，停下以后谁会被跳过？harness 在哪些时刻留了观察的口子，最贵的那一步有没有被看到？
