1Reson8 开源 0.5B 语音识别模型 Rumble-2-Flash，CEO 称小到能在手机上跑

端侧语音小模型语音识别开源

来源：@reson8_official（阿姆斯特丹语音识别公司 Reson8 官方账号）；@raoulritterr（Reson8 CEO Raoul Ritter）；Hugging Face 官方博客。发帖日期：2026-11-18。

Reson8 今天把 Rumble-2-Flash 以 Apache 2.0 开源权重发布，模型为 0.5B 参数，支持 40 多种语言，架构沿用 Qwen3-ASR，可直接在 Hugging Face Transformers 和 vLLM 里运行，无需自定义运行时。公司在 Hugging Face 博客里介绍，它是用 on-policy distillation（并由 GOLD 对齐不同分词器）从更大的生产模型 Rumble-2 蒸馏而来。官方给出的评测是：在 Open ASR Leaderboard 多语种轨道上，中、德、法、意、西、葡、印地、荷、英 9 种语言平均错误率 6.96%，优于大 15 倍的 Meta omniASR-LLM 7B，也高于 Whisper large-v3；英语轨道平均 WER 为 6.6%。在 AppTek 302 小时、覆盖 14 种英语口音的呼叫中心测试上，WER 为 7.86%，与 30B 的 NVIDIA Nemotron 3.5 Transcribe（7.78%）接近，并好于同族的 Qwen3-ASR 0.6B（8.7%）。吞吐方面，官方称在批次较满时超过 7,000 RTFx（约半秒处理一小时音频），模型卡标明这些榜单数字是在 H200 上用 vLLM 测的，不能直接当成手机端延迟。CEO Raoul Ritter 在帖子里写它「比大 20 倍的模型更好，小到能在你的手机上跑」，但官方模型卡和博客没有给出手机机型、内存占用或端侧时延。该模型面向预录音频（通话、讲座、语音备忘、播客）；说话人分离和实时对话转写被放在更大的 Rumble-2 上。托管 API 已于 11 月 3 日上线。

对端侧 Agent / App 的启发 0.5B 级、面向电话噪音和口音的开源 ASR，正好卡在手机语音助手最需要的那一层：先在本地把语音稳妥转成文字，再决定哪些请求继续在端上处理。若要接到 iOS 语音助手里，下一步不是复述服务器上的 7,000 RTFx，而是自己在神经引擎或 Core ML 上量延迟、功耗和中文/口语场景的 WER；同时不要指望它单独承担实时多说话人对讲，官方已把那部分留给更大模型。

2ChatGPT 上线 Live Dictation：边说边出字，并取消 10 分钟上限

语音输入移动 AppChatGPT实时转写

来源：@ChatGPT（ChatGPT 官方账号）；OpenAI ChatGPT 更新说明。发帖日期：2026-11-18。

OpenAI 宣布升级 ChatGPT 的听写：Live Dictation 会在说话的同时把语音转成文字，而不必等你说完再一次性出稿。官方更新说明还写明，可以点按或点击波形来显示或隐藏正在生成的文字，并取消了原先 10 分钟的录音上限。该功能正在全球向所有 ChatGPT 套餐推送，覆盖 iOS、Android、网页和桌面应用。这不是新的对话式语音模式，而是输入框里的实时听写；OpenAI 未在这篇说明里公布所用模型和端侧/云端分工。

对端侧 Agent / App 的启发 手机语音助手的输入体验，正在从「说完再等」变成「边说边改」。端上至少应该先做低延迟的流式转写和即时纠错，让用户在说错一个词时就能改，而不是把一段长录音交给云端再一次性回写。取消时长上限也说明：长指令、长备忘会成为常规输入，端侧缓冲、标点和局部重识别要比一次性离线转写更值得优先做。

原帖：官方帖 @ChatGPT · OpenAI 更新说明

3DoorDash 助手向美加全部 iOS 用户开放，可在信息 App 里完成点餐结账

移动助手iMessage垂直 Agent小模型

来源：@AIatDoorDash（DoorDash 应用 AI 研究实验室官方账号）；@andyfang（DoorDash 联合创始人兼 CTO Andy Fang）。发帖日期：2026-11-18。

在今年早些时候的试点之后，DoorDash 宣布其助手已对所有用户在 iOS 信息 App 中开放，基于 Apple Messages for Business。用户可以自然语言下单，例如「25 分钟内送到、20 美元以内、不要蘑菇、加辣的拉面」，在同一对话里看到带照片、描述和价格的可点选菜单，自定义餐品并完成结账，无需打开 DoorDash 主应用。官方称助手会使用 DoorDash 订单历史和内部 memory blocks 做个性化推荐；当请求同时包含预算、饮食偏好和送达时间时，由小语言模型和机器学习排序在多家门店中搜索符合全部约束的菜系和单品。其他示例还包括：提醒明天中午点午餐、把食谱链接转成到店购物车、查找附近最便宜的新款 AirPods。DoorDash 联合创始人兼 CTO Andy Fang 确认面向美加全部 DoorDash iOS 用户，并称 Android 支持即将到来。入口为 doordash.com/text。

对端侧 Agent / App 的启发 这是一条很完整的「系统级消息通道 + 垂直 Agent」路径：意图、约束、菜单预览和支付都留在 iMessage 里，不强迫用户跳进自家 App。做端侧语音或消息助手时，可以把预算、忌口、时效这类硬约束先在本地收成结构化条件，再用小模型做检索和排序，把带图的可点选项和结账确认做成系统对话卡片。Android 尚未同步，也说明这类体验目前仍深度绑在 Apple Messages for Business 上。

4Google 发布 Gemini 4 Neon：介于 Carbon 与 Hydrogen 之间，面向复杂编程与知识工作

Gemini智能体编程模型移动 App

来源：Koray Kavukcuoglu（Google DeepMind 高级副总裁、Google 首席 AI 架构师），Google 官方博客；@GoogleDeepMind、@GeminiApp。发帖日期：2026-11-18。

Google 发布 Gemini 4 Neon，定位在 Gemini 4 系列的 Carbon 与 Hydrogen 之间，强调在复杂软件工程、知识工作和科学流程上，既有接近前沿的能力，又能较快完成端到端任务。官方称在 Artificial Analysis Intelligence Index 的 xhigh 思维档上总分为 61、总体第 3，并领先于同档可比模型；在 Vals Index 上第 2（70.9%），处在帕累托前沿；新的 Agent Arena Index 上可操纵性（中途按用户修正调整）排第 2，并在 4,200 多场真实智能体会话中以 1336 分列全球第 2。定价为每百万 token 输入 3 美元（缓存输入 0.15 美元，官方称优惠 95%）、输出 15 美元，上下文窗口 100 万 token。官方还给出一批基准，包括 Artificial Analysis Coding Agent Index 总体第 1（58.6）、Terminal-Bench 4.1 为 65.2%、FrontierCode 2.0 在默认 high 设置为 46.2%，以及内部 Antigravity 测试中「目前最低的捏造率」。@GeminiApp 确认，Google AI Pro 和 Ultra 订阅用户可在移动端、桌面和网页的 Chat 与 Tasks 模型列表中选用 4 Neon；开发者可通过 Google AI Studio 付费 API 和 Android Studio 使用，Antigravity 亦向付费 Pro/Ultra 开放。以上分数和成本对比均来自 Google 官方。

对端侧 Agent / App 的启发 云端模型线进一步把「够快的前沿推理」单独做成一档，并直接进到 Gemini 手机应用的 Tasks。端云分工可以更明确：端上继续承担低延迟交互和任务草稿，把长程分析、编程和科学工作交给这一档更省成本的云端模型；既然 Tasks 已能切换 Neon，手机助手也应让用户（或策略层）按任务难度选模型，避免一律走最贵、最慢的那一档。

原帖：Google 官方博客 · 官方帖 @GoogleDeepMind · 官方帖 @GeminiApp

5Genie 4 向 Google AI Ultra 用户开放：可在探索中途改世界，并生成同步原生音频

世界模型具身智能Genie仿真

来源：Diego Rivas（Google DeepMind 集团产品经理）与 Pavan Kumar（Google Labs 集团产品经理），Google 官方博客；@GoogleDeepMind。发帖日期：2026-11-18。

继 10 月 27 日的研究发布之后，Google 今天把 Genie 4 正式放入 Project Genie，向符合条件的 Google AI Ultra 订阅用户开放，Pro 用户可排队。Genie 4 被官方称为目前最逼真、可交互的世界模型：你可以在探索过程中用新提示实时改环境，例如改天气、加入角色或改变剧情；并首次为这些画面配上随场景变化的实时原生音频，包括环境声和角色对白。同期还有 Project Genie agent，可用自然语言组织多模态模型来生成初始视觉和配乐；探索时也可引入 Gemini，观察画面、给出下一步建议或自动触发事件。Genie 3 仍可选用，单次生成探索时长从 60 秒延长到最多 3 分钟，并支持世界串联、360 度全景图作为初始条件，以及实时自然语言事件。官方同时提醒：这仍属前沿研究，摄像延迟、复杂物理交互、实时音频精度和长期场景持续性仍是未解决问题；所有生成的视频和音频带有 SynthID 水印。模型卡还写明输出为最高 24fps 的实时 720p 视频加同步音频，并依赖 Gemini Omni Flash 与 Gemini 的推理来保持连贯。

对世界模型 / 具身智能的启发 世界模型正在从研究演示变成可订阅的交互环境，关键能力是「边走边改」和同步音频，而不是一次性生成一段视频。对机器人或端侧智能体来说，更有价值的是：在允许真实动作之前，先在可提示、可打断的仿真里预演；同时也要正视官方自己列出的限制——物体持久性和复杂物理仍会漂，不能把当前 Genie 当成可靠的物理引擎。这套体验目前在浏览器里、且仅向 Ultra 开放，还不是手机端侧能力。

原帖：Google 官方博客 · 官方帖 @GoogleDeepMind
