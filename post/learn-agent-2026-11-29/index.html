Agent 学习笔记 · 2026-11-29

记忆双路径写入打架、无时间戳冲突、静默空召回与记忆投毒

约 7 分钟#learn-claude-code#Memory

覆盖范围：learn-claude-code s09（持久记忆），以及对照业界主流做法（Anthropic Memory tool、Claude Code 自动记忆、LangMem、Letta 与 Anthropic 2026-11 记忆分层）。今天做了四件事：用选择题清了 8 道积压复习（8 对 7）；画清 s09 怎么挂在 agent_loop 入口和出口两个插槽上、补齐业界省掉的 4 个核心机制；跑通 5 个独立会话的跨会话读写与过滤；做了“过时记忆冲突”和“外部文档记忆投毒”两组破坏实验。

今天最大的收获是：记忆系统的写入所有权必须单一，且内部子调用同样绝不能静默失败。实测里，因为没在工具层禁止主模型直写 .memory/，主模型自己动手覆写记忆文件、与后台提取逻辑打架，甚至无沙盒用 bash 跑到全局配置文件里写规矩；而入口的 select_relevant_memories 写死 200 token 被推理模型思考吃光后，静默返回空数组，连关键词兜底都没触发。

今天学了什么

1. s09 怎么和 Harness 配合工作。s09 在原来的 while True 循环体里一行没动，只在循环外侧加了两个插槽：

位置做什么谁来跑
入口插槽（进循环前，每轮 1 次）把“用户最近问题 + MEMORY.md 目录”交给一次独立的轻量模型调用，挑出 ≤5 条编号，读正文连同目录拼进 system prompt轻量模型 + 代码拼接
循环体内（while True 跑 N 圈）s01–s08 照常运行（s08 只压 messages，不动 system 里的记忆），s09 不出场主模型 + 工具/Hooks
出口插槽（Stop 放行后、return 前）调模型从对话里抽长期候选（带 `scope: persistentcurrent_task）→ 代码 should_store_memory 硬过滤临时词与重复 → 写盘并重建 MEMORY.md；攒满 10 条再触发 consolidate_memories` 合并整理（带快照回滚）提取模型 + 代码把关

2. 课程省掉的 4 个业界机制。

  • 写入路线（Hot path vs Background）：要么走热路径（如 Anthropic memory tool，给模型专用记忆工具在对话中当场读写，目录与普通文件工具隔离），要么走后台/离线提取（如 LangMem、Letta 睡眠时 agent、Anthropic dreaming），两条路线边界必须划清。

  • 大规模检索：记忆攒到几百几千条时连目录都装不下，业界改用向量检索 / 混合检索先粗筛再精排。

  • 记忆认知分类：除了事实/偏好（语义记忆）和过往经历（情景记忆），业界还有程序记忆——直接改写 agent 的做事规则或 system prompt，写错一条就会系统性带偏以后所有会话，风险最高。

  • 三层分层与防投毒：Anthropic《The components of agent memory》把跨会话记忆分成原始记录 → 原子笔记（类似 .memory/*.md）→ 结构化表示（wiki/图谱），并靠离线 dreaming 淘汰旧记忆；同时严防跨会话记忆投毒。

3. 5 会话实测 trace：撞见“双路径写入打架”。 模拟退出重开跑了 5 个全新会话：S1 写入缩进偏好 → S2 新会话 0 工具调用直接答出 Tabs → S3b 在 3 条记忆里只召回缩进、没加载喝茶和数据库 → S4“本次会话不要建文件”被成功过滤没落盘。

但 S3a 出了意外：.memory/ 建好后，system 里暴露了 Memory catalog，却没告诉主模型“记忆由系统自动保存，不要自己改 .memory/”。结果主模型一听“Remember both”，自己跑了 6 圈、8 次工具调用去读旧记忆格式、亲手用 write_file 写新记忆并覆写 MEMORY.md，把 harness 的 scope、临时词过滤和自动索引重建全绕过去了。

4. 破坏实验 A（过时记忆冲突）& 实验 B（记忆投毒）抓出 4 类真实故障。

实验现场发生了什么暴露的机制缺陷
A1（立旧规矩）.memory/ 还没建，主模型为了“真记住”，用 bash 绕过只管文件工具的 permission_hook，直接新建了全局 ~/.claude/CLAUDE.md（测试完已删净）无 OS 沙盒，bash 越界写不受限
A2（改新规矩）主模型先试 rm 删旧记忆被拦，转头用 write_file 把旧文件覆写成“【已废止】”并手改索引，还因为 system 没给日期自己脑补写成了 2025-11-29双路径打架；记忆缺系统时间戳，靠模型脑补必出错
A3（新会话验收）入口 select_relevant_memories（写死 max_tokens=200）被推理模型 thinking 吃光预算，正文输出空串 ""；extract_json_array("") 不抛异常直接返回 []，连关键词兜底都没触发内部子调用静默失败，把截断当成“无相关记忆”
B1（含毒外部文档）vendor_doc.md 用 HTML 注释伪装“用户长期偏好”，主模型识破并警告用户；但 extract（max_tokens=1000）同样思考耗尽输出空串轻量内部调用必须关 thinking 或给足预算并校验返回

5. 记忆投毒（Memory Poisoning）的 3 步链条与防线。 记忆投毒本质上是把“一次性提示注入”升级成“跨会话永久后门”：攻击者在外部文档/网页里伪装成项目规范埋毒 → 混过提取写进 .memory/ → 以后全新会话把它召回进高信任级别的 system prompt 长期发作（哪怕删了原文档毒还在）。

原则： 防记忆投毒不能只靠提示词写“当数据看”，要三道防线叠加：来源标记（Provenance，外部文档默认不可自动写入高危规则/程序记忆）+ 变更可见/人工确认 + 工具层沙盒与权限硬兜底。

我理解对的

  • 看到 S1 vs S3a 立刻指出根因：模型自己写和 harness 写是两套设计，在逻辑上打架。

  • 准确理解 select_relevant_memories 的角色：独立于主循环的另一次轻量模型调用，按“用户问题 + 目录”联合筛选，不是随便挑。

  • 针对实验 A/B 提出的三条设计修改意见全部切中要害：

    1. 必须在 OS 沙盒里运行，禁止绕过 harness 做越界和直写操作；

    2. 由 harness 用系统时钟给记忆加时间戳，实现留新去旧；

    3. 给足预算，且子调用绝不能静默返回空串，必须返回带错误码的显式错误，由 harness 按错误码走降级兜底。

我理解错的、不够准的

修正： 复习 c034 选错了 A，误以为黑名单补齐关键词就能拦住、沙盒能阻止工作目录内的所有删除。其实 bash 写法无穷永远穷举不完，沙盒只按资源（允许的目录/地址）拦越界，管不到允许范围内的删改。

修正： 我猜测 s09 没满 10 条记忆时像“栈（后入先出）”一样按最新的来。实际 s09 没有时间戳、按文件名字母序排、撞 slug 甚至会拒新留旧；真正要留新去旧，必须由 harness 加系统时间戳并做冲突覆盖/失效标记。

修正： 我在“推 blog 规矩”里觉得忘掉比记错更糟。这个单向例子确有道理，但放到一般场景（尤其旧规矩是“不用问直接删/推线上”），记错/过时更糟：忘掉时模型知道自己不知道会来问或查文档，脏记忆会被自信地反复带进每个新会话的 system 静默做错事。

修正： 我把 recall_select 撞上 max_tokens=200 说成了“context 满了”。其实不是输入上下文满，而是输出上限太小被推理模型的 thinking 吃光（stop_reason=max_tokens）；不过“抛显式错误码由 harness 兜底”的修法完全对路。

举一反三

1. 拒绝静默失败要推广到 harness 内部子调用。不只是 run_bash 给主模型不能吞报错，recall_select、extract_memories、summarize_history 这些内部模型调用一旦截断或解析失败，也必须抛显式错误码，不能默默降成 [] 或 "(empty summary)"。

2. 时间与来源元数据必须由 harness 写，不能让模型自己填。模型既会脑补错年份，也容易混淆“用户亲口吩咐”和“外部文档里的文字”。

举一反三： 评审任何一个带记忆的 agent，先问四件事：主模型能不能直接改记忆文件（所有权是否单一）？记忆有没有系统时间戳和冲突失效机制？筛选/提取调用截断时会静默变空还是触发降级？外部工具读进来的文本能不能自动变成长期规则？

还没解决的问题

思考题： 记忆按认知类型分语义、情景、程序三种，其中程序记忆会直接修改 agent 自己的规则或 system prompt。如果给团队的 agent 加上程序记忆，你会允许它全自动生效，还是必须人工审批？边界画在哪里？
