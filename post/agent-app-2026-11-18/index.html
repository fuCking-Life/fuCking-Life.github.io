每日 AI 与移动端智能体简报（2026-11-18）

1. Gemini 任务模式对免费用户开放，可代打电话、付账单并购物

相关度 5/5。标签：移动助手、任务代理、Gemini 4 Hydrogen、语音与短信。

来源：@GeminiApp（Google Gemini 官方账号）；博客作者 Josh Woodward（Google Labs、Gemini 应用与 AI Studio 副总裁）。发帖日期：2026-11-17。

Google 宣布，Gemini 应用中的 Tasks（任务模式）即日起对美国、日本、韩国、加拿大、澳大利亚和印度的数亿免费用户开放，底层改用新的 Gemini 4 Hydrogen。用户把主界面从 Chat 切到 Task 后，可以把事项交给助手：例如同时给附近店铺打电话并在排队中等待、约到时间后写入 Calendar；经授权访问公用事业账户和邮件，分析异常账单；按 Agent Payments Protocol（AP2）走 Visa、Mastercard 的数字化支付代币购物（American Express 为即将支持），可预设消费上限，下单前仍会向用户确认，票据进入 Google Wallet。官方称 Wallet 即日起扩展到 iOS。美国用户还可把邮件转发到 gemini@google.com，或在 Android / iOS 上设置「Text with Gemini」用短信交代任务（需符合条件的美国号码和运营商）。任务跑在 Google Cloud Agent Compute Engine 的硬件隔离虚拟机里，并配有注入过滤和 Safe Browsing。Google 也承认任务仍可能中途失败，部分网站最后一步还得交回用户手动点。

对端侧 Agent / App 的启发 这是云端个人助手在「打电话、代付款、跨应用收尾」上的又一次加码，但关键路径仍然是确认购买、隔离执行、以及可随时打断。端侧语音助手不必复刻整条代购链路，却很适合先在本地完成意图澄清、消费上限和「何时必须问一声」，再把不可逆的调用交给云端；Wallet 扩展到 iOS，也让后续的支付确认更适合做成系统级生物识别，而不是应用内随便点一下。

原帖：Google 官方博客 · 官方帖 @GeminiApp

2. 清华团队提出 DroidPrefill：把手机 GUI 智能体改成「预填充决策」，步骤延迟最高降 85%

相关度 5/5。标签：端侧 Agent、手机 NPU、GUI 智能体、小模型。

来源：董啜、蔡冠宇、王继良（清华大学）与姜雨辰（北京理工大学），论文作者。发帖日期：2026-11-16。

这篇 arXiv 论文针对「完全在手机上跑 GUI 智能体」：现有流水线把云端那套长推理、逐步解码搬到端上，既吃不准 NPU「预填充快、逐 token 解码慢」的特点，又和静态编译的固定上下文配置冲突。DroidPrefill 先把当前界面编译成可执行候选，再在固定上下文预算里只保留关键 UI 和任务状态；预填充结束后直接看候选标签的 logits，有把握就用 Self-Speculative Action Dispatch（SPAD）立刻执行，没把握再走一段短的结构化求精，只有需要填文本时才额外生成。实验在小米 17（骇龙 8 Elite Gen 5）上，经 GenieX 走 QAIRT/W4A16 和 llama.cpp/Q4_0（Hexagon NPU），文本侧用 Qwen3-4B-Instruct，无云端参与逐步决策。AndroidWorld 上，相对自回归 T3A+ 基线，QAIRT 路径单步推理从 24.2 秒降到 4.6 秒（约 80.8%），Easy 成功率从 10.7% 升到 23.0%；llama.cpp 路径从 34.8 秒降到 5.2 秒（约 85.0%），Easy 成功率从 13.1% 升到 37.7%。输出从每步约 319 token 降到约 27 token。需要注意：Medium+Hard 成功率仍然很低（最高约 7.3%），评测时模拟器和任务控制器在主机上，手机负责观测解析与决策。

对端侧 Agent / App 的启发 端侧 GUI 智能体不该照搬云端「先写一长段 reasoning 再吐动作」。把动作空间收成候选、把决策尽量提前到 prefill 边界，4B 级模型在旗舰 NPU 上才有机会把单步从半分钟打到约 5 秒。若要在 iOS 上做类似能力，值得先看 Core ML / 神经引擎能否同样暴露预填充边界的候选 logits，并老实接受：容易的点击任务可以上端，难任务仍需云端或更强的本地规划。

原帖：论文 arXiv:2611.20772

3. 荣耀与北科大评测：0.75B–4.7B 本地智能体的成败，很大程度取决于 harness

相关度 5/5。标签：端侧小模型、Agent Harness、本地部署、荣耀。

来源：王浩（北京科技大学）与黄婷（荣耀终端有限公司），论文作者。发帖日期：2026-11-16。

论文《Harness Leverage Across Model Size》同时改变模型和套件：5 套已发布的 harness、18 个要产出工件的任务、4 个可本地部署的开源模型（0.75B 到 4.7B）外加 35.5B 锚点，用同一套确定性检查器给 360 个组合打分。作者的核心观察是：对共享 8GB 显卡、只有几十亿参数的本地模型来说，harness（如何拼提示、暴露工具、判断何时结束）往往决定任务能不能完成，而不只是快一点慢一点。名为 Mingbird 的「完成控制型」harness 在每个规模上都拿到最高平均分。367 个有效组合里，有 127 个没有写出任何声明的产物，其中 85 个还是「正常退出」——如果只看进程退出码，会把没交出东西的运行算成成功。单独拿掉一条防止重复空转的规则后，0.75B 模型分数掉 0.411，18 个任务里有 8 个完全没有产物。作者也说明，harness 优势随模型变大是扩大还是缩小，现有四个尺度还定不下来。

对端侧 Agent / App 的启发 在手机或 8GB 级本地环境里，先把「何时停、有没有把文件写出来、如何挡住重复失败」做硬，往往比换一个稍大的小模型更管用。不要用「agent 进程成功退出」当完成标准，一定要检查产物；给 1B 上下的端侧模型写套件时，重复调用熔断和完成门禁值得做成默认能力，而不是等模型自己学会收尾。

原帖：论文 arXiv:2611.21407

4. Google AI Studio 可用一句提示生成可上架的全栈 Android 应用

相关度 4/5。标签：Android、AI 编程、Gemini、移动开发。

来源：@GoogleAIStudio（Google AI Studio 官方账号）；博客作者 Mike Taylor-Cai（Google AI Studio 产品经理）。发帖日期：2026-11-17。

Google 宣布，AI Studio 里的 Build agent 配合 Gemini 4 Carbon / Hydrogen，可以从一条提示生成带数据持久化、登录和 Gemini 能力的 Kotlin / Jetpack Compose Android 应用，并发布到个人 Google Play 资料库，用普通 Google 账号就能装到真机，无需自己管签名和 USB 调试。后端会按需开通 Cloud Firestore、Firebase Authentication（Google 登录）以及 Firebase AI Logic + App Check，把模型调用放在服务端，避免把 API key 写进 APK。浏览器内模拟器支持更低延迟启动、1200p、实时音频（可测 Gemini Live、TTS 等），并能一键截屏交给 agent 改 UI。这是对今年 5 月 I/O 上「在 AI Studio 里做 Android 应用」的一次明显加码，目前看不到同步的 iOS / Swift 生成能力。

对端侧 Agent / App 的启发 移动端 Agent 应用的脚手架正在被「提示 → 工程 → 上架」压缩，但密钥、鉴权和 App Check 被明确留在云侧。若你在 iOS 上走类似路线，更该提前设计：哪些推理必须在端上、哪些通过代理调用；同时，带音频的模拟器说明语音助手类应用已经是这类生成工作流的一等公民，Swift / 端侧模型这条线目前还得自己补。

原帖：Google Developers 博客 · 官方帖 @GoogleAIStudio

5. OpenAI 发布 GPT-6.2 Astra 与 GPT-6.2 Sol，强调更少 token 完成专业与智能体任务

相关度 4/5。标签：大模型、智能体、ChatGPT、API。

来源：@OpenAI（OpenAI 官方账号）。发帖日期：2026-11-17。

OpenAI 发布 GPT-6.2 代的两个模型：Astra 面向更难的专业项目（幻灯片、表格、文档、编程与前端，以及科学研究），Sol 面向日常工作和多步智能体流程。官方称两者都能用更少的输出 token 完成高难度任务，从而在额度内多做一些事。在其「Agents’ Last Exam」专业多步评测上，OpenAI 称 Astra 比 GPT-6 Astra 高 5.2 分、成本不到三分之一，并比 Claude Fable 5.2 高 5.5 分、成本约为其 5%（该榜对 Fable 5.2 排除了 9 道使用了后备模型的题）。Cognition FrontierCode 2.0 上，官方称最大推理力度下 Sol 与 Astra 只差 0.5 分，成本大约为五分之一。API 方面，Astra 输入/输出定价较 GPT-6 Astra 低 20%（官方标为每百万 token：输入 8 美元、缓存输入 0.40 美元、输出 40 美元）；Sol 维持 GPT-6.1 Sol 的价格。即日起在 ChatGPT Work 与 Codex 向 Plus、Pro、Enterprise、Edu 开放，也同步提供 API。Pro 的 200 美元档首次为 Sol 提供 Ultrafast（官方称最高约 4.5 倍速率，但更耗额度），500 美元档则两个模型都有 Ultrafast。以上分数和成本对比均来自 OpenAI 官方，尚未见到完整的独立复现。

对端侧 Agent / App 的启发 云端模型这一轮拼的是「同样额度下多完成几件多步任务」，不是再堆一轮炫耀性生成。端云分工可以更干脆：本地小模型负责低延迟交互和工具草稿，把长程专业任务交给更省 token 的云端模型；同时要为「更快但更吃额度」的档位预留开关，避免语音助手在连续多步时把用户的云端配额一次打光。

原帖：OpenAI 官方博客 · 官方帖 @OpenAI

6. Cognition 推出 Devin Bots：持久智能体负责目标，并可带领一组 Devin

相关度 4/5。标签：编程智能体、多 Agent、长期任务、Android。

来源：Cognition（Devin 开发公司）官方博客。发帖日期：2026-11-17。

Cognition 发布 Devin Bots：带有自己的记忆和工具、能并行带领多个 Devin 会话的持久智能体。你交给它的是一项持续责任（例如「让 Android 与 iOS 保持对等」），而不是一张任务清单；它负责调查、分派、验收，只把需要人拍板的事项送进 Needs You 收件箱，并可在 Slack、iMessage 或 Devin 应用里汇合。官方案例包括：没有 Android 工程师的情况下，一个 Android Bot 用 44 天做出已进入 Google Play 开放测试的 Android 应用，合并 1,134 个 PR、约 34.5 万行 Kotlin；人类负责人只发了 183 条消息，其中 22 天一条都没发，此后还由该 Bot 持续跟 iOS 新功能对齐。另一个 Layout Bot 负责网页布局抖动，三周合并 159 个相关 PR。同事 Jenny Xu 的手游工作室在只有她一名人类员工、约 20 个 Bot 的配置下，周 PR 从约 50 个升到约 1,900 个，并保持每周发版。Cognition 还称内部上周约合并 1,600 个来自 Bots 的 PR，公司整体每周合并超过 2,000 个 PR。产品已在 devin.ai/bots 上线，官方未在这篇博客里公布定价。这些产出数字均来自 Cognition 自述。

对端侧 Agent / App 的启发 这里展示的是「目标所有权 + 人只处理决策点」，不是更快的自动补全。做手机助手时，可以把长期责任（跟进、对等、回归）和单次任务分开：端上保存目标、约束和待确认队列，云端或远程编码智能体负责推进；iMessage 被列为交互入口，也说明移动端更适合做简短决策通道，而不是把全部仓库上下文塞进手机。

原帖：Cognition 官方博客

7. Google 为 Antigravity 上线 Robotics 插件，用 Gemini 4 Hydrogen 当更快的机器人工作台

相关度 4/5。标签：具身智能、机器人、Gemini 4 Hydrogen、仿真。

来源：Alex Gruenstein（Google Distinguished Software Engineer）与 Gabe Cohen（机器人产品高级总监）及 Gemini Robotics 团队，Google Developers 博客。发帖日期：2026-11-17。

在 Gemini 4 Hydrogen 发布之后，Google 今天为 Antigravity 推出 Robotics 插件，把硬件接入、MuJoCo 仿真和闭环控制收成一套技能，官方说法是「一下午可以从拆箱走到可运行的应用」。Hydrogen 把原先 Gemini Robotics ER 2 的具身推理能力收进 Gemini 4 系列，并可用自然语言目标加摄像头画面直接规划、写控制代码并在执行中调整。官方称在 Artificial Analysis Robotics 0.1 上，Hydrogen 控制真实六轴机械臂完成 8 项桌面任务，得分 58，与更高端的 Argon 相近但 token 成本更低；在公开 ERQA 上，空间推理也超过 ER 2。演示包括约 10 分钟完成 I2RT YAM 机械臂接入与标定、一小时内从白板草图走到传送带分拣，以及双臂肥皂店接单打包。Antigravity 需 Google AI Pro 或 Ultra；API 侧可直接调用 gemini-4-hydrogen。这些基准和用时均来自 Google 官方演示与陈述。

对具身智能 / 端侧 Agent 的启发 机器人这一侧也在把「快而够用的模型 + 可组装的技能层」当成默认工作台，而不只是堆更大的专有模型。这和手机端侧智能体是同一思路：把接入、仿真/预演、感知和闭环控制拆成可调用技能，让模型在固定工具边界里迭代。端侧不一定要直接控机械臂，但「先在本地或仿真里预演，再允许真实动作」值得写进任何会操作外部设备的语音助手。

原帖：Google Developers 博客
